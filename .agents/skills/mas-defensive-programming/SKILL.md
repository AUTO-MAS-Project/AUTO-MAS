# MAS 反防御性编程规范

让主流程依赖明确的契约，在真实失败边界处理错误。新增分支必须保护当前可达行为；必要的外部校验、安全措施和恢复能力继续保留。

## 先追溯，再决定是否加分支

读实际调用方、初始化入口、模型校验、任务基类与已有故障处理，确认数据经过哪些约束。对拟增加或删除的防御逻辑，明确：

- **来源**：哪个受支持的入口、旧数据版本或运行故障会触发它。
- **已有保证**：此前在哪一步完成了校验或处理，该调用路径是否一定经过它。
- **失败语义**：拒绝输入、向上报错、恢复还是使用默认值；谁负责把失败转成用户可见结果。

用代码和契约支持判断，无需新增审批表。Python 类型注解、变量名或“正常不会发生”不能证明运行时保证；没有校验保证且确实可达的输入，应在所属边界处理。

## 分支准入

| 情形 | 处理方式 |
| --- | --- |
| 用户输入、HTTP/WS、外部进程响应、文件或持久化数据进入系统 | 在拥有该数据的边界校验并给出明确失败；内部复用已建立的保证 |
| 配置容器、validator 或任务基类已保证字段与生命周期 | 直接使用其契约，移除同一路径上重复的 `None`、`getattr`、空值纠正与重试 |
| 网络、磁盘、进程、并发或取消可能失败 | 保留实际需要的超时、清理、锁释放与回滚；复用已有处理入口 |
| 仍受支持的旧版本或旧数据 | 在兼容入口转换一次，说明适用范围；临时补位标明移除条件 |
| 只有绕过初始化的测试替身或假想未来调用才会触发 | 修正测试或调用方，不增加生产兜底；测试取舍按 [mas-testing](../mas-testing/SKILL.md) |

内部不变量被破坏时暴露可定位的错误，不静默改成空列表、默认配置或成功结果。合法空值、可选字段和业务默认值按原契约处理。

## 异常与恢复

- 在能做出有效处置的层捕获已知异常；不能恢复时保留原始原因向上传递，避免每层重复记录同一失败。
- `except Exception` 只用于确需隔离失败的任务、进程或服务边界，并有明确的失败结果与诊断信息；记录日志本身不构成吞异常的理由。任务 `on_crash` 的自保护要求按 [mas-function-design](../mas-function-design/SKILL.md)。
- 默认值和降级必须属于受支持契约，不能让保存失败、任务未执行或解析失败表现成成功。关键配置损坏不得以空配置覆盖原数据。
- 重试放在已有集成边界，有明确的可恢复错误、次数或时间上限，并核对重复副作用；尊重取消，不在内部辅助函数叠加重试。
- 清理、锁、事务、资源生命周期和安全校验属于正确性保证；精简代码时保留它们。配置变更遵循 [mas-data-model](../mas-data-model/SKILL.md)，不另造补偿或恢复框架。

## 审查与交付

检查本次触及的分支是否有可达来源、是否重复既有保证、是否把失败变成成功。删除前核对所有实际调用路径及受支持版本，不能仅凭类型、当前测试未覆盖或本地未复现判定为死分支，也不顺带清扫无关模块。

验证保留下来的真实失败处理和正常行为，复用最小相关检查；依据与未覆盖路径随交付说明。测试数量和新增 guard 数量均不作为质量指标。
