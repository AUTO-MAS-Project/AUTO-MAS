# 采集与交付

## 运行环境

在应用源码工作区读取 `frontend/e2e/run.mjs`、`frontend/playwright.config.ts`、`frontend/e2e/fixtures.ts` 及相关页面。环境准备与启动规则由 [mas-e2e](../../mas-e2e/SKILL.md) 维护；依赖来自该版本的锁文件，不安装第二套执行框架。

普通浏览器 E2E 使用开发服务器。正式教程截图需要对应版本的发布构建 renderer，或实际 Electron 窗口；切换版本文字、隐藏开发入口不能证明发布版画面一致。浏览器加桥接仍是浏览器环境，原生窗口、托盘与文件对话框需要单独验证。

首批试验使用的做法：

1. 在指定版本工作区建立临时采集配置，继承现有 Playwright 配置与隔离后端，只将前端服务改为发布构建的 preview。构建时注入的后端端口、桥接 HTTP/WebSocket 端口与隔离后端一致；preview 使用单独的前端端口并绑定 `127.0.0.1`。后端监听范围以该版本启动代码为准：首批基线的 `main.py` 监听 `0.0.0.0`，隔离数据根不代表网络隔离，health URL 为回环地址也不限制监听范围。
2. 发布构建不自动启用浏览器 Electron bridge。需要时在页面脚本执行前注入该版本已有桥接；先核对 `frontend/src/utils/browserDevElectronAPI.ts` 的导入与初始化依赖。不要直接把依赖开发条件的模块塞进生产 bundle。不能复用时记录阻塞，不另造一套应用状态。
3. 固定语言、时区、明暗主题和窗口尺寸。定时示例按界面时区核对，API 时间按该版本的序列化约定换算后比较。截图前确认开发菜单不存在、目标可见、字体已加载且没有未处理错误。只叠加教学编号或框线、关闭动画和光标，不改变配置值、隐藏失败提示或隐藏开发入口冒充发行版。

临时配置和采集脚本要在本次工作区实际建立后才运行。以下是调用形式，不是仓库已内置的教程命令；配置文件名与 tag 使用本次创建的值，从 `frontend/` 执行：

```text
yarn e2e --config <capture-config.ts> --grep <tutorial-tag>
```

保持由 `run.mjs` 创建临时数据根，关闭复用现有服务；不启用就地模式，不连接用户日常实例。一次只选一个主题，下一主题另开一次运行。按所选版本的源码约定配置运行环境，隔离后端显式使用 development；不能仅凭 `.env` 文件存在推断应用环境。

## 流程与截图

使用稳定的可见名称或页面语义定位元素。动作后等待对应响应或可观察状态，保存类动作检查响应并刷新回读；不把固定 sleep 当成功条件。演示数据可以通过公开 MAS 接口准备，教程声称演示的步骤仍需由页面实际操作。

以整个教程的执行结果决定是否采用产物：退出码为零但全部跳过、缺图或最终断言未运行均不算通过。每篇在独立输出目录完成后再进入候选区，保留上次确认产物，避免中途失败留下新旧混合图。逐主题结果包含命令、退出结果、实际执行数、关键断言和截图清单。

截图保留足够的导航上下文。对照原图检查标注是否挡住按钮、选项或正文，截图裁切是否遗漏前置开关；敏感信息用演示数据替代。截图清单与文章引用一一对应，失败截图只用于诊断。

## 文档采用与来源

沿用目标文档仓库的资源约定。VitePress 中同时使用 `<img>` 与可点击原图时，确认构建后的两种 URL 都有效；首批使用 `public/docs/img/<batch>/`，因为普通 Markdown 图片可能被构建为带 hash 的资源，而原图链接未必同步改写。批次路径使用相对站点 URL，不写作者本机绝对路径。

同批保存机器可读的来源记录，至少包含：应用 tag/commit、源码是否有修改及其范围、构建方式与运行环境、语言/时区/主题/窗口、实际制作者、主题结果和截图清单、关键断言、未执行范围。附运行命令时去掉凭据和机器专属配置；浏览器桥接、网络拦截与截图标注等采集调整也要记录。

在候选文档上运行其现有构建命令，然后访问实际预览检查图片、原图、章节跳转和窄屏显示。已有本地对照页若放在构建输出目录，重新构建前备份、完成后恢复；预览服务器可能缓存文件清单，新增静态文件后按实际需要重启。

交付中分开说明：本次实跑结果、既往试验、未验证能力。纯浏览器配置教程不能写成完整桌面应用、真实游戏或通知投递已经验证；失败主题不进入发布候选。
