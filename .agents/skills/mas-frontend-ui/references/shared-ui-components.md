# Shared UI Components

Prefer the unified primitives exported from `@/components/ui` (and `@/composables/useConfirm`) over hand-rolling raw Ant Design Vue wrappers or page-local layout CSS.

## Component Map

| Need | Prefer | Key Props / API | Notes |
| --- | --- | --- | --- |
| Dialog / form modal | `AppModal` (`@/components/ui`) | `v-model:open`, `size?: 'sm'\|'md'\|'lg'\|'xl'\|'full'` (`480/600/760/960/90vw`), `width`, `title`, `subtitle`, `icon`, `footer?: 'confirm'\|'close'\|'none'\|'custom'`, `okText`, `cancelText`, `okDanger`, `okDisabled`, `submitting`, `dirty`, `sessionKey`, `scroll?: 'body'\|'none'`, `layer?: 'default'\|'nested'\|'blocking'` | Defaults to `centered` and `destroyOnClose`. `submitting` syncs confirm loading and locks `closable`/`keyboard`/`maskClosable`. `dirty` triggers an unsaved-changes confirm before closing; pass `sessionKey` (or bind `:key`) when reusing one modal across different edited entities so a stale confirm never closes a newly opened edit. Inherits 32px Electron title-bar avoidance via `styles/appOverlays.css`; forwards extra AntD `a-modal` props via `$attrs`. Slots: `header`, `header-extra`, `default`, `footer-left`, `footer`. |
| Imperative confirmation | `useConfirm` / `openConfirm` (`@/composables/useConfirm`) | `confirm({ tone?: 'danger'\|'warning'\|'info', title, description?, okText?, cancelText?, width?, maskClosable?, zIndex?, onOk? }): Promise<boolean>` | Defaults to `centered: true`, `wrapClassName: 'app-confirm-modal'`, and `okType: 'danger'` for `tone: 'danger'`. Pass `Modal.useModal()` host when inside a scoped `ConfigProvider` theme. `onOk` rejections stay open instead of resolving `true`; cancel resolves `false`. |
| Destructive / confirm action button | `ConfirmActionButton` (`@/components/ui`) | `risk?: 'low'\|'high'`, `tone`, `title`, `description`, `okText`, `cancelText`, `danger`, `type`, `size`, `disabled`, `loading`, `confirm: () => void \| Promise<unknown>` | `risk="low"` uses `a-popconfirm`; `risk="high"` uses `Modal.useModal()` + `useConfirm`. Prevents duplicate clicks and tracks async `confirm` loading automatically. |
| Page root shell | `AppPage` (`@/components/ui`) | `layout?: 'scroll'\|'fill'`, `maxWidth` | Use `scroll` for normal scrolling pages and `fill` for viewport-bound split/scrollable panes (e.g. history, plugins, logs). |
| Page header | `PageHeader` (`@/components/ui` or `@/components/PageHeader.vue`) | `title`, `subtitle`, `icon`; slots `leading`, `title`, `meta`, `search`, `actions` | Reuses `.app-page-header` / `.app-page-title` tokens from `styles/pageTitle.css`. |
| Page content surface | `PageSurface` (`@/components/ui` or `@/components/PageSurface.vue`) | `variant?: 'surface'\|'section'\|'transparent'`, `padding?: 'none'\|'sm'\|'md'`, `scrollable` | Applies `.app-page-surface` / `.app-page-section` backed by `--app-appearance-surface-bg`, providing custom-background opacity and nested transparent surfaces without adding page selectors to `appearanceSurfaces.css`. |
| Section container | `SectionCard` (`@/components/ui`) | `title`, `subtitle`, `icon`, `variant?: 'card'\|'plain'\|'sub'`, `density?: 'default'\|'compact'`, `collapsible`, `v-model:collapsed`, `anchorId`; slots `title`, `actions`, `default`, `footer` | Keeps `.form-section > .section-header > h3` so anchor layouts continue collecting headings. Use `plain` for flat form sections and `sub` for framed nested subsections. |
| Loading / error / empty boundary | `StateView` (`@/components/ui`) + `NoData` | `loading`, `error`, `empty`, `loadingTip`, `emptyTitle`, `emptyDescription`, `emptySize?: 'sm'\|'md'\|'lg'`, `minHeight`, `overlayLoading`, `@retry`; slots `loading`, `error`, `empty`, `empty-action`, `default` | Renders a centered spinner inside an explicit `minHeight` box (avoiding zero-height origin drift), `ApiRetryAlert` for errors, and `NoData` for empty states. |
| Script / user config edit shell | `ConfigEditShell` (`@/components/ui`) | `loading`, `error`, `loadingTip`, `maxWidth`, `surface`, `@retry`; slots `header`, `banner`, `default`, `footer`, `overlay` | Composes `AppPage`, `PageSurface`, and `StateView`. Set `:surface="false"` when wrapping legacy `ConfigLockPanel` + `a-card` pages incrementally. |
| Existing form/status primitives | `SettingRow`, `StatusChip` (`@/components/ui`) | See component props | Use `SettingRow` for label-to-control rows inside `SectionCard`, and `StatusChip` for finite status indicators. |

## Extension Rules

1. Keep wrappers thin: accept semantic presets (`size`, `variant`, `density`, `tone`, `risk`) and forward native Ant Design Vue attributes via `v-bind="$attrs"` (`inheritAttrs: false`) instead of mirroring every AntD prop.
2. Drive variations with props and `--ant-*` / `--app-*` tokens, never by coupling shared components to page-specific ancestor class names.
3. Keep default chrome quiet: render optional subtitles, icons, or footer notes only when explicitly supplied by the caller; avoid decorative emojis and filler explanatory copy.
4. Keep overlay geometry in `frontend/src/styles/appOverlays.css` and surface transparency in `frontend/src/styles/pageSurface.css` / `appearanceSurfaces.css` rather than duplicating portal or background overrides per page.
