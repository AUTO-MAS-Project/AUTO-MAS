# 验证与交付

## 分层说明证据

| 验证层级 | 能证明 | 不能据此声称 |
| --- | --- | --- |
| 类型、lint、格式、静态调用链 | 声明一致、构建约束、接线位置 | 事件实际产生或入库 |
| 运行真实 helper 的受控探针 | 结果映射、去重、关联、开关代次和字段拒绝 | 真实 UI/硬件/游戏正确 |
| 禁用生产遥测的浏览器 E2E | 用户入口与业务状态、现有 UI 行为 | 生产事件接收 |
| 隔离打包端与本地接收器 | preload/IPC、主进程策略、实际传输契约 | 全部业务入口正确或正式入库 |
| 明确授权的生产单条验收 | 指定版本/事件实际可查询 | 所有事件/场景完成真实验收 |
| 明确授权的真实脚本/设备运行 | 实际执行到的业务结果及相应样本 | 不同专项和未执行分支都已验证 |

台账“已接入”、契约样本数量、CI 全绿都不能替代真实入口验证。已验证的历史 head 不代替本次修改后的 head。

## 有意义的最小验证集

按受影响边界选择，不机械为每个页面铺测试。修改已有 bug 时先让旧实现复现，再证明修复：

- 正常完成、明确业务拒绝、网络异常、取消/跳过；必要时覆盖前段成功后后段失败。
- 重复完成、HTTP/WS 先后反转、旧请求后返回、导航/卸载/替换。
- 操作开始后关闭再开启：旧操作不发送，新操作仍可发送；开关本身不发事件。
- 跳过/恢复快照不计新操作；批量汇总不逐项发；逻辑操作不会在多组件或两层 wrapper 重复。
- 使用真实入口的 target 身份核对固定类型，不用两个虚构脚本 ID 代替“用户 ID/脚本 ID”混合情况。
- 所有新事件字段经真实 `validateAnalyticsEvent`/`AnalyticsService` 接收；额外字段、自由文本、嵌套值、未知枚举和不允许的 renderer 事件被拒绝。
- 不增加业务请求，不等待统计网络；需要保留取消能力的 API 包装仍返回原 Promise，异常和响应仍按既有契约处理。

对首页刷新，至少覆盖“首载中两次点击但只有一次 fetch”“正常手动新批次”“多来源组合 Promise 稳定”“全部 busy 跳过”“部分来源刷新”和失败分类。

不要写读取源码断言某个字符串存在的测试；调用真实可导入逻辑并 mock 生成 API、Electron IPC、WS 和时钟边界。临时测试放 `frontend/debug/` 等忽略目录，用单独 Vite Plus 配置显式运行，遵守 [前端测试政策](../../../../frontend/TESTING.md)。

## 命令与环境

本仓库 Windows 开发使用 PowerShell 7。源码 Electron 与独立后端默认开发环境，无需 `.env`；验证生产行为须显式传入 `AUTO_MAS_ENV=production` 并使用隔离数据根与本地接收器。不要输出凭据。

在 `frontend/` 中，按本次变更执行适用检查：

```powershell
$env:AUTO_MAS_TELEMETRY = 'disabled'
$env:AUTO_MAS_ENV = 'development'
yarn lint
yarn typecheck
yarn format:check
yarn test --maxWorkers=4
```

Electron 代码变化另跑 `yarn build:main`；需要验证 Renderer 构建时跑 `yarn exec vp build`。依赖与 CI 规则由 `mas-ci-checks` 负责，不能用 `yarn test` 代替类型或构建检查。

业务路径有变时结合 `mas-e2e`，从 `frontend/` 使用唯一入口：

```powershell
yarn e2e:check
yarn e2e --grep '@smoke|@settings|@recovery'
```

根据本次流程选择标签，不照抄无关全量。真实脚本、扫码、升级与硬件不能用受控响应冒充；继续遵循会话已有授权，不自动操作真实账号和设备。

本地接收器必须使用隔离数据根/进程配置并确保生产请求数为零。要证明发送层时用合成字段和仅向本地传输的依赖注入；不能通过删除真实环境保护来让开发源进生产库。明确授权的打包端验收另行记录版本、事件、请求数和清理结果，恢复被临时改动的测试入口/配置。

## 文档与 PR 交付

在已有 PR 描述或交付说明中简要交代：

- 本次复用/新增/修正的事件和真实结果所有者。
- 什么算受理、完成、取消、未知和部分完成；哪些子入口未覆盖。
- 字段白名单、采样/汇总、去重与关闭行为是否变化；采集范围变化时三语说明已同步。
- 运行的命令、具体 head、实际结果，以及本地/生产/真实业务各自的验证边界。

按当前代码更新 `analytics.md` 和 `analyticsCoverage.md`。不要把场景数除以事件族数当完成率，不把同一请求的多种触发结果加总成独立请求量；带采样、限频和断线丢弃的样本不是权威全量运行计数。

延续仓库提交规则：功能专属探针默认不提交；已有 PR 只保留一个更新日志碎片；本 Skill 不自行授权提交、推送、合并、评论或服务器修改。
