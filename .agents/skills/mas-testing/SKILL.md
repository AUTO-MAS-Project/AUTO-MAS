# MAS 测试规范

**改代码先查旧测试，按“必测区 / 免测区”分流：必测区必须补或改 1～2 个精准用例，免测区不写新单测。** 禁止因偷懒跳过必测区，也禁止为了凑数堆砌无用单测。

## 1. 第一步：必须先查并跑旧测试

修改任何模块前，先搜对应域的已有测试（`tests/` 或同目录 `*.test.ts`）并运行：
- 已有测试覆盖该模块 → **优先在原文件修改或追加断言**，不另开新文件。
- 旧测试已过时或锁死旧实现 → 按第 4 节清理或重写，不能放任不管。

## 2. 第二步：必测区 vs 免测区

### ✅ 必测区（必须补或改 1～2 个用例，不得跳过）

| 改动类型 | 必须验证什么 | 入口要求 |
| --- | --- | --- |
| **公共契约与协议** | API 路由、配置读写与升级、声明式 schema、插件挂载与 `src_adapter` 联调 | 走真实路由 / 真实配置类 / 真实组件渲染 |
| **高损失状态机** | 并发保存队列、配置锁、原子写盘、快照恢复、任务取消与崩溃清理 | 隔离文件或真实状态机，断言最终落盘/终态 |
| **非静态工具能抓的真实 Bug** | 肉眼和 lint 抓不住的时序/逻辑错误，**先复现红、再修复绿** | 从用户可触发的公开入口复现 |
| **关键链路 E2E** | 页面不可达、前后端 HTTP/WS 协作（见 `mas-e2e`） | 隔离浏览器 E2E，不造假响应 |

### ⏭️ 免测区（0 新增测试）
纯文档、文案/样式/布局调整、简单透传、类型或拼写修复 → 只跑 `typecheck` / `lint` / 已有测试或页面核验，**不写新单测**。

## 3. 第三步：硬禁令与数量上限（防假测试与堆砌）

命中以下任意一条**禁止入库**（正反例见 [tests.md](tests.md) 和 [mocking.md](mocking.md)）：
1. **禁测私有实现**：直接调 `_helper`、断言内部调用次数/顺序、私有字段初值、固定日志文案。
2. **禁测 Mock 本身**：mock 被测模块，或单个用例连 mock ≥ 3 个内部函数，最后只断言 `assert_called_*`。
3. **禁手搓假对象**：用 `SimpleNamespace` / 缺字段假 dict 代替真实 Pydantic / Config 模型。
4. **禁铺量穷举**：同一条逻辑按参数/页面复制多个雷同用例（每条契约只留 **1～2 个**代表样本，优先参数化）。
5. **禁测静态工具能抓的错**：类型错、必填字段漏传、语法/导入错误交给 `typecheck` / `lint` / Pydantic。
6. **禁读源码当测试**：`readFileSync` / `open()` grep `.vue`/`.ts`/`.py` 文本（i18n 词表扫描与跨语言协议检查除外）。

**数量刹车**：常规 PR 新增 **1～2 个用例**即可；超过 3 个新用例必须逐条写出“删掉它会漏掉哪个**不同**的生产故障”，写不出来就合并或删掉。

## 4. 存量清理 3 问（命中即删）

除 `tests/AGENTS.md` 标明受保护的用例外，审查或重构时命中任意一条**直接删除**：
1. **改坏核心逻辑测试还能过？** → 假测试，删。
2. **生产入口根本造不出测试里的输入或 mock 状态？** → 不可达，删。
3. **只锁死历史内部拆法或一次性的旧补丁？** → 实现锁，删。

交付只报：查了哪些旧测试、公开入口与关键断言、实跑命令与结果、未覆盖范围。
