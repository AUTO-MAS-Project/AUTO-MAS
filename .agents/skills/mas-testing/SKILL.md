# MAS 测试撰写规范

本次验证与测试入库是两个决定。**默认不新增长期测试**；测试数量、覆盖率或“每个 Bug 补一个测试”均不是完成标准。

## 长期入库四步判定

1. **说清可达故障**：写明「真实入口 → 触发前提 → 用户可观察损失 → 边界断言 → 现有覆盖缺口」。仅内部函数能拼出的状态不算可达故障。
2. **先复用已有覆盖**：已有用例能抓住则直接复用，缺少断言优先扩展原场景；公共保证在公共边界测，专项只测接入差异。
3. **权衡长期收益**：只有持续节省的人工回归与避免的损失大于维护成本时才入库；低风险样式/文案用本次页面核验，一次性验证留本地。**高损失例外**（数据损坏、泄露、不可恢复、安全/进程/文件越界）在边界可稳定验证时优先保留，删除前须有等效或更强证据。
4. **选最低成本层级执行**：在能暴露目标错误的最低层停止，不机械升格为 GUI/E2E。

| 目标错误 | 最小充分验证 |
| --- | --- |
| 文档、格式、文案或低风险外观 | 静态检查或本次页面核验（不新增长期行为测试） |
| 公共函数、接口、协议或隔离存储错误 | 对应单元测试/契约测试（写盘契约读真实隔离文件，不只断言 mock 被调） |
| 页面不可达 / 界面与 HTTP·WS 协作错误 | 相关标签隔离浏览器 E2E（见 `mas-e2e`） |
| 进程退出、文件替换、网络、权限、原生 IPC | 承担保证的真实集成测试（隔离账号与用户数据） |
| 真实 Runtime、脚本、模拟器或游戏行为 | 作者本机 `@real` 验收（请求受理/mock 不替代真机结果） |

## 编写与反模式红线

编写断言读 [tests.md](tests.md)，隔离外部依赖读 [mocking.md](mocking.md)。

- **独立预期**：期望值必须来自需求/契约，禁止跑一遍现行代码把输出抄成答案。
- **不测实现细节**：禁止断言内部调用次数/顺序、固定日志文案、私有字段初值、方法转发、样式值或 `readFileSync` 源码片段；同义输入只留最小代表，不按页面/参数铺量。
- **Bug 回归证据**：用相同输入证明「修复前因目标错误失败、修复后通过」（无法跑基线时明确说明）。
- **边界隔离**：只在系统边界隔离外部依赖，复用 `tests/AGENTS.md`（后端）与 `mas-frontend-standards`（前端）既有夹具，不另造测试框架或测试专用生产接口。
- **存量清理**：逐条按收益举证——无可达场景或仅锁死当前实现的测试可直接删除（明确受保护的用例保留；MFW 族的核心最小回归已随实现交给积木仓库，宿主只守升级链路 `tests/core/test_plugin_config_upgrade.py`）；合并替代时先补断言并跑通再删旧用例。

交付按「场景 → 可观察断言 → 执行命令与结果 → 未覆盖范围」报告。
