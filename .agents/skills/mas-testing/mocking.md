# Mock 红线（只隔离外部边界）

Mock 的唯一用途是**隔开慢、不稳定或有副作用的外部世界**（网络、磁盘路径、子进程、时钟、Electron IPC）。被测业务逻辑必须跑真实代码。

## 允许 vs 禁止

| ✅ 允许隔离（系统边界） | ❌ 禁止 Mock（内部业务） |
| --- | --- |
| 临时目录 / 隔离配置根（复用 `tests/AGENTS.md` 夹具） | 正在测的业务判断、校验器、配置模型、保存队列 |
| 外部 HTTP 请求、子进程退出码、系统时钟 | 用 `SimpleNamespace` / 缺字段假 dict 冒充真实 Config 对象 |
| 前端生成的 API 客户端、Electron IPC | 连 mock 3 个以上内部 helper 拼出“能跑通的假流程” |

## 3 条硬规则

1. **Mock 返回值必须符合真实契约**：不能为了测试通过，编造生产接口不可能返回的字段或状态码。
2. **用完必须还原**：用 `monkeypatch` / `vi.mock` 局部替换调用方查找的符号，禁止全局污染其他用例。
3. **不为测试改造生产架构**：需要大量 mock 才测得动时，说明入口选错了或根本不该写单测——不要为了“方便 mock”给生产代码加多余的抽象层或测试专用接口。
