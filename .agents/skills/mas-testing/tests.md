# 断言正反例（写测试前对照）

只看公开入口的**最终结果**（返回值、落盘文件、HTTP 响应、渲染输出），不看内部怎么实现。

## 正反例速查

| 场景 | ✅ 这样写（测结果） | ❌ 禁止这样写（测实现 / 假测试） |
| --- | --- | --- |
| **配置保存** | 写入隔离配置根 → 重新加载 → 断言字段值 | mock `save()` 然后 `assert_called_once()` |
| **并发/保存队列** | 延迟第一个请求 → 连续提交两次 → 断言最终快照保留两次改动 | 断言内部数组长度或 `_flush()` 被调次数 |
| **接口错误处理** | 边界返回 `code=500` → 断言前端抛错、列表未删除、不播成功提示 | 写死测试里 `try/except` 吞错并断言返回 `None` |
| **声明式表单** | 真实 schema → 渲染控件 → 触发变更 → 断言回传值通过后端校验 | `readFileSync` 检查 `.vue` 文件里包含某行代码 |
| **通知重试** | 只在网络边界注入超时 → 断言最终结果与实际发出次数 | mock 掉重试函数本身，再断言它被调用 |

## 3 条硬检查

1. **预期不能抄代码**：期望值必须来自需求或真实样本，禁止运行一遍现行函数把输出贴成 `expected`。
2. **不把 Bug 写成预期**：缺翻译、缺字段应该修代码，不能写一个“缺翻译时退化显示原始 key”的测试把它固化下来。
3. **改坏必红**：写完后心算或临时改坏目标逻辑——如果测试还绿，这条测试是废的，立刻重写或删掉。
