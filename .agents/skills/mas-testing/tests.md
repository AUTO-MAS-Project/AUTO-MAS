# 行为断言与用例规模

## 选择断言

先说明参数或结果出错会使调用方出现什么功能问题，再选能观察该契约的入口；不能只用“确实生成了参数”证明保留价值。以下是断言边界示例，具体名称和调用方式以当前实现为准：

| MAS 场景 | 有效证据 | 证据不足 |
| --- | --- | --- |
| 配置持久化 | 在隔离配置根通过真实提交、持久化入口写入，再加载核对值 | 只断言赋值成功或 mock 的保存函数被调用 |
| 写入对象定位与字段对应 | 沿真实请求、标识和字段追到持久化对象，在负责该关系的边界验证 | 在各业务对象上反复用“修改 A 后 B 不变”间接探测共同写入关系 |
| 调度派发 | 从调度入口观察选中的任务、参数和调度结果 | 只测测试代码自己写的选择循环 |
| 通知重试与去重 | 注入传输故障后核对最终结果、发送内容及实际发送次数 | mock 掉重试逻辑，再断言该 mock 被调用 |
| 前端更新期间禁用操作 | 触发更新状态并定位对应控件，核对禁用状态 | 统计页面共有几个 disabled 属性 |

有公开读取入口时用它检查写入；契约本身是文件或边界请求时，直接检查隔离文件或请求内容，无需只为测试新增生产接口。边界调用次数只有在重复执行本身影响契约时才值得断言。

共享队列的保存与重置时序由队列本身负责，可以在执行真实队列逻辑时控制外部读写完成的顺序。跨对象隔离若是共享存储边界自身的契约，也应在该边界覆盖，而不是让每个业务页面和日期各自维护一组邻项断言。

## 检查预期与区分能力

- 预期来自需求、领域规则或已核实样本。例如给定调度时区和固定当前时间，预先确定下一次执行时间；不能调用被测计算函数生成期望值。外部脚本成败须来自已核实的上游结果契约，不手造日志标记来证明适配层自定判定。
- 功能缺失或代码缺陷应推动修复，不做以“出现 Bug 时会退化”为通过条件的退化测试。例如 i18n 缺失应补齐翻译，不以显示原始标题作为正确结果。已确认的数据恢复、明确报错等故障处理仍按其责任边界验证。
- 把目标结果改错、漏掉副作用或重复执行，测试应失败。风险较高或断言含糊时做一次针对性的临时改坏验证，完成后恢复；不要求每个用例跑全套变异测试。
- 保持契约不变而调整内部函数拆分时，测试应继续通过。断言源码含某个字符串、AST 分支或继承写法不能证明运行行为。
- 资源清单、打包内容和隔离导入闭包本身可以是交付契约；按其风险保留检查，不能与业务源码形状断言一并删除。前端跨语言契约检查按 [mas-frontend-standards](../mas-frontend-standards/SKILL.md) 执行。

## 控制规模

按故障与责任边界识别重复覆盖，不按用例名、参数或专项目录判断独立价值。同一故障与契约的重合用例应合并、参数化或抽象为公共测试，混合用例仅清理重合部分。某层已有覆盖时，新增另一层测试须说明它独有的契约。

跨专项的共同初始化、准备失败后的收尾、更新与恢复保证，在公共边界集中验证实际生命周期行为；专项测试只验证独有的接入差异，不逐个锁定私有字段初值。若通用入口尚在计划中，记录待迁移关系和现有缺口，不把待建公共测试当作已有替代覆盖，也不分别复制同一套场景。

审查存量按其保护的行为及替代证据判断，不能为减少数量或让重构通过而削弱有效断言；保留与删除按 [tests/AGENTS.md](../../../tests/AGENTS.md)。
