# 配置初始化性能与事务边界设计

- 状态：按用户确认的统一事务模型修订，作为本轮实现与验收依据。
- 日期：2026-10-26。
- 关联：[PR #1651](https://github.com/AUTO-MAS-Project/AUTO-MAS/pull/1651)。
- 范围：新配置基类的事务组织、初始化性能和必要调用方适配；MCP 不在本轮范围内。

## 1. 目标

快速赋值与逐字段赋值只改变事务边界的位置。保留逐字段严格校验、即时 Init 信号、公开对象身份和原有部分成功规则，减少正常首次加载中的工作区重复构造与合并。

事务上下文统一管理边界并派发提交、回退；节点保留自己的工作区和操作方法，激活标记单独管理本次操作，不再按初始化状态选择特殊事务实现。

## 2. 一种上下文，两种进入方式

`transaction()` 和 `transaction_sync()` 默认加入当前有效事务，没有父事务时建立根事务。同一执行者的普通嵌套调用不增加上下文或保存点；在边界内部捕获异常不会自动将该事务标记失败。

显式 `transaction(new_boundary=True)` 或同步等价入口建立新的局部回退边界。它仍属于父事务，成功只向父层合并，失败只撤销本层；父事务之后失败会一起撤销此前合并的子层结果。没有父事务时，该入口本身成为根事务。

只有根事务发布 live、递增持久化根修改代次，并接续既有保存流程。子边界不独立发布或落盘。

所有边界使用同一个 TransactionContext 类型和一条当前上下文链。上下文记录父层、真实执行者、有效期、暂存作用域及已登记的节点/类，不增加 Init/shared 模式、失败粘滞标记或并行的初始化事务栈。

## 3. 保留节点持有工作区的原有结构

节点实例在 `_workspace` 中按事务 scope_id 保存自己的壳；信号工作区继续在节点类的 `_signal_workspace` 中按同样的 scope_id 保存。增加索引是为了支持多层局部边界，工作区数据不放在 manager 或 TransactionContext 中。

`effective` 和 `signal_effective()` 在本节点/类上沿当前事务父链查找；首次写入从本边界之前可见的状态复制。底层提交统一加入当前事务，不根据 INITIALIZING 选择特殊工作区。

节点 `_COMMIT(ctx)` 负责向父工作区或 live 逐字段回填，保留分组及成员身份；`_ROLLBACK(ctx)` 负责删除本层工作区并恢复相关激活标记引用。信号分别由 `_COMMIT_signal(ctx)`、`_ROLLBACK_signal(ctx)` 处理。manager 保留登记列表，只调用这些原有职责的方法，不代替节点应用或撤销数据。

父层此前没有工作区时建立自己的独立壳，避免退出子层的引用变成父层直接写入口。显式父工作区引用在子层赋值时也先取得子层副本，不能绕过局部回退。登记列表及暂存作用域在统一退出入口清理，不重复清理工作区。

可变字段仍只支持复制后整字段赋值；原地容器修改不属于事务保证，本轮不扩展深层代理、保存点日志或信号撤销记录。

## 4. 初始化调用方

Entry 原逐字段流程在每个字段赋值、提交之外显式建立局部边界；字段异常在该边界退出后收集，使成功字段可以保留。

activate(fast_init=True) 选择在当前 Entry 的整个字段循环外建立一次局部边界。内部字段操作自动加入它，保持顺序、校验和即时信号。字段或直接信号链失败时，异常穿出该边界，事务完整撤回本次尝试，随后从首字段执行原逐字段流程，不保留本次成功部分。

递归 Entry 分别尝试和回退。集合初始化在每个成员的 add/commit 外显式建立局部边界，保留成员失败隔离。文件读取、载荷迁移、身份分配、嵌套集合激活及框架引用订阅维持既有位置，不进入当前 Entry 的字段重试体。

已有显式父事务不妨碍快速赋值；新局部边界仍受该父事务最终提交或回退控制。嵌套 Entry 有自己的明确字段边界，可以在其失败边界退出后自行恢复逐字段流程。

暂存作用域检查、同节点初始化再入限制及取消后的清理保留。取消不自动重试；提交或清理本身的内部错误沿框架传播，不被逐字段重试掩盖。

## 5. 重复调用的责任

启用快速赋值允许失败尝试和逐字段流程重复触发信号、调用接收者和第三方服务。配置基类不扫描回调、不识别副作用、不去重、不代替接收者提供幂等性。

合法跨节点访问按正常权限加入当前事务，其受管修改跟随所属边界回退；不因跨节点本身退快，也不给 is_locked 等读取增加退快副作用。

外部 IO、进程操作、删除守卫等既有非字段副作用和不受支持的原地修改，不因事务统一而获得额外回退保证；本轮不增加通用副作用恢复机制。

## 6. 构造时关联整个激活操作的标记

节点自己的 NodeState 与整个激活操作的标记是两个值。共享标记统一在 `__init__` 接收；未显式传入时，从直接父节点承接仍在进行的标记。`build()` 不增加专用参数，递归 `activate()` 直接复用实例上已关联的引用；没有进行中的标记时，激活入口创建一次标记。无父节点、未关联标记的独立实例仍开始自己的激活操作，不因调用者处于初始化而加入其激活链。

激活标记不通过 ContextVar 传递，不通过父节点查找，也不附带根节点身份、代次或独立执行者上下文。标记只保存本次快速赋值选择、调用链是否仍在执行及所属根事务的弱引用。

入口开始时将当前已构造子树关联到该标记，覆盖尚未轮到自身 activate 的子节点；后续成员在构造时承接同一引用，激活调用无需再次传入。完成激活的父节点不向后来创建的成员传递旧标记。失败后恢复本层相关标记引用，重试仍使用该操作的标记，不因字段退快创建新生命周期。

整个调用结束后入口修改标记。热态服务仍需等待节点为 ACTIVE 且根事务完成；同一根事务内允许入口结束后的关联编辑。真实 Task/Thread 与事务有效期直接复用既有事务检查，不另外建立激活执行者上下文。

按用户本轮确认，限制只覆盖本次激活树；初始化回调对树外已稳定节点的取锁、解锁、登记等操作按原热态规则处理，不因调用者处于初始化而额外禁止。对树内节点，快慢路径都拒绝未完成激活时的热态操作；其他执行者的非法修改在修改或等待入口之前拒绝。

file/name 继续在构造和启动准备时登记，构造的声明登记完成后关联内部传入的标记；activate 不搬运登记逻辑。manager 集中拒绝对本次激活树内未就绪节点的登记变更，保留 UUID 先确定、live 身份及文件仅关联根节点等约束。

外部 IO 和树外热态操作的副作用沿原机制处理，不因快路径失败获得新的回退、去重或冻结保证。

### 写入与生命周期检查的落点

`_require_write_access()` 统一处理受管写入的激活参与资格、整次激活阶段和热态锁/删除约束。冷态字段赋值、初始化赋值仍可执行；本节点已 ACTIVE 而整次激活仍在执行时拒绝热态修改。入口已经结束但所属根事务尚未发布时，同一执行者仍可关联编辑，其他执行者没有参与资格。

普通字段和集合操作在 `_stage` 检查，工作区字段直接赋值在分组写入口检查。`update` 通过原字段赋值与 commit 执行，不再重复检查同一组权限。含实际暂存的 commit 在等待入口之前检查；取得入口后仅复核等待期间可能变化的锁和删除状态。空提交、空更新以及集合原有的幂等跳过不新增写权限检查。

`_require_lifecycle_access()` 只拒绝尚未发布的激活树上的生命周期变更，用于 file/name 登记、公开实例订阅/解订阅、删除守卫登记/移除和解锁；它不要求节点已 ACTIVE，保留原有冷态声明。锁、触发器和稳定导出继续使用 `_activation_ready` 检查整体就绪。触发器在实际派发处检查，False/None 空操作不增加热态门槛，已删除节点不能派发。

公开信号订阅的生命周期检查放在描述符入口，内部 `_connect_impl` / `_disconnect_impl` 不重复检查；初始化建立引用订阅继续走内部入口及原信号工作区。没有实例发送者的类级声明不添加节点阶段限制。读取、校验、内部信号派发、工作区建立与提交/撤销不添加热态门槛。

## 7. 其他调用方与兼容边界

业务层普通 transaction()、transaction_sync()、effective、字段赋值与 commit 接口维持默认语义。通知配置的成组更新继续由显式根事务保证整体回退；专项中读取 effective 的调用保持有效视图语义。

旧 Init/shared 特殊事务入口移除；保留节点工作区、提交、撤销及信号方法的总体结构，不另建兼容转发层。

Init/runtime 事件仍根据节点阶段生成，与事务是否具有父层、是否新建局部边界无关。model_dump 保持导出调用对象存储状态的规则，持久化和管理器导出仍在事务外执行。

既有内部属性访问、字段复制合并和安全 C YAML 优化保留；文件继续通过原有原子读写入口处理，不新增读写封装或依赖回退。

## 8. 验收

1. 普通嵌套复用、显式局部回退、子成功父失败及多层嵌套的值和对象身份正确。
2. 父层暂存不能被子层消费，子层遗留暂存按原要求报错并清理；取消不泄漏入口资格。
3. 配置和信号工作区一致服从边界，父层引用不能越过子层写入，退出上下文不能恢复权限。
4. 快慢路径值、严格验证顺序和即时信号前缀一致；失败先完整回滚，再执行原字段循环。
5. 合法关联写入按边界恢复，第三方调用允许重复；不扩展额外副作用保证。
6. 构造登记、递归、运行时 add、类型替换、取消与重激活维持契约；标记在构造时关联，树外稳定节点不受调用者阶段限制。
7. 子事务不单独递增保存代次或落盘，根成功按原 commit/flush 契约处理。
8. 同步、异步、线程与 Task 入口保持真实所有者检查及原有等待规则。
9. 首次空配置、正常 YAML 和扩展成员规模用隔离副本、独立进程测量，报告样本数、中位数和结果一致性；不把配置阶段收益当作完整启动收益。
