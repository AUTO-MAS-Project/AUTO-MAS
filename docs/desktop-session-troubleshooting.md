# 桌面分身环境修复指南

在分身窗口找到与下列标题或提示相同的一项，按对应步骤处理。命令请在管理员 PowerShell 中执行。处理后回到分身窗口，点击「重新检测环境」。

## 远程桌面服务或任务计划程序服务

先确认服务是否存在及其状态：

```powershell
Get-Service -Name TermService, Schedule | Select-Object Name, Status, StartType
```

- **「已停止」**：运行 `Start-Service TermService` 或 `Start-Service Schedule`，只启动对应服务。
- **「尚未运行」**：等服务状态稳定后重检。若变为已停止，按上一项处理。
- **「已禁用」**：请管理员确认禁用原因。设备策略允许时，由管理员恢复服务的启动设置，再启动服务。
- **「不存在」**：确认 Windows 版本具备所需能力，再尝试下文的系统文件修复。仍缺失时，请管理员检查系统安装。
- **「状态无法读取」**：在管理员 PowerShell 中运行上面的查询。如果命令也失败，把报错提供给设备管理员。

## 「无法加载」系统组件、找不到 `termsrv.dll` 或无法确认文件签名

这个步骤适用于 ATL、远程桌面 ActiveX 和 Windows 凭据保护组件加载失败，也适用于原生 `termsrv.dll` 缺失或无法确认签名。依次运行：

```powershell
DISM.exe /Online /Cleanup-Image /RestoreHealth
sfc /scannow
```

等待第一条命令成功完成，再运行第二条。修复完成后重启并重检。如果重检仍失败，请把命令结果一并反馈。避免手工替换 DLL 或重建系统服务。

## 「远程桌面服务未使用原生 DLL」或「远程桌面服务未配置 ServiceDll」

如果装过 RDP Wrapper、SuperRDP 等工具，用原工具的卸载功能撤销改动，再重启重检。若未安装过这类工具，或卸载后仍失败，请管理员检查系统服务配置。

## 「本机设置关闭了远程桌面」或「组策略禁止远程桌面连接」

本机设置关闭且设备允许接收远程桌面连接时，由管理员开启远程桌面并保留网络级别身份验证。组策略禁止时，由策略管理员决定是否调整。分身使用本机连接，无需配置路由器端口转发。「远程桌面已被关闭」等通用提示也应先核实策略和本机设置。

## 「本机 RDP 端口配置无效」或「找不到预期的本机 RDP 监听」

- **端口配置无效**：请管理员恢复有效的监听端口。默认端口为 3389。
- **找不到监听**：先处理同时出现的服务或策略提示，再重检。仍失败时，运行 `Test-NetConnection localhost -Port 3389`，使用自定义端口的设备请换成实际端口。若无法连通，请管理员检查服务监听和端口占用。

## 子会话、登录和系统版本

- **「Windows 子会话未就绪」**：如果检测确认子会话开关已关闭，且其他必需检查已通过，点击「启动」会尝试启用。若仍失败，请确认 MAS 以管理员身份在当前用户已登录的桌面运行，再重试。
- **「无法读取 Windows 子会话开关」**：在已登录的桌面以管理员身份重开 MAS。仍失败时，先处理同时出现的系统组件或服务错误。
- **「系统可能只允许 Windows Hello 登录」**：先用 Windows 账户密码连接，PIN 无法代替密码。密码验证失败且确认只允许 Hello 登录时，个人设备可按需关闭该限制，注销后重新登录。受管设备请联系管理员。
- **「请在已登录的交互桌面打开 MAS」**：登录本机桌面后，从该桌面重新打开 MAS。
- **「仅支持 Windows 10 1809 及以上或 Windows 11 客户端」**：升级到符合要求的 Windows 客户端版本。
- **「检测到 Windows 家庭版」**：这是版本提示。若设备缺少分身所需的远程桌面主机能力，升级到支持该能力的版本，例如专业版，再重检。
- **「请使用 Windows x64 和 MAS 的 x64 Python」**：使用 x64 Windows 和 x64 MAS。若从源码运行，确认后端使用 x64 Python，再重新启动。

若仍无法启动，反馈时附上 Windows 版本、失败的检测项和「查看分身日志」中的对应报错。请勿附上账户密码。
