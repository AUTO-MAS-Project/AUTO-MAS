# 桌面分身

「设置 → 桌面分身」提供独立的队列和托管任务选择，以及手动启动入口。分身连接后由主会话中的 MAS 派发所选任务。留空时只显示子桌面。主页快速开始仍在主会话启动。分身任务可在同一个调度页监控和停止。配置了完成后电源操作的队列需要先改为「无操作」。

## 实现路径

1. Electron 的 `desktopSessionHandlers` 校验来自 MAS 窗口的 IPC，在独立 Vue 窗口显示控制栏。它将预览区的坐标换成物理像素，交给父会话的 Python 宿主。
2. `app.core.desktop_session.host` 通过 ATL 的 `AtlAxCreateControlEx` 承载系统 `mstscax.dll`。ActiveX 使用 localhost、CredSSP、固定子桌面尺寸及 SmartSizing。后台最小化解除原生预览与 Electron 窗口的所有者关系，再把预览移到屏幕范围外。原生最小化直接最小化承载窗口。
3. 登录后用 WTS 确认子会话。任务计划程序用 `RunEx` 指定会话与当前账户的 SID，通过 `pythonw.exe` 启动无界面的 `app.core.desktop_session.executor`。宿主校验客户端的 PID、会话和 SID，执行器校验自己的会话和内核报告的服务端 PID。执行器确认实际分辨率，再装配现有 `TaskManager`，由托管模块启动脚本和游戏。Electron 界面只运行在主会话。
4. Electron 通知主后端停止受理，确认任务、更新、配置与历史已收尾，再允许子后端取得同一工作目录的 Windows 文件锁。控制端切换主窗口的 HTTP 和 WebSocket 到子后端，同时保留原调度状态模型。批次结束后关闭子后端，再拉起主后端。主后端恢复既有定时器，避免重复启动队列。

## 凭据和诊断

首次连接成功后保存 `config/desktop-session/credentials.json`。该文件以 Windows 账户为键，值是 DPAPI-NG `LOCAL=user` 密文的 Base64。密码经 Electron 的私有进程管道交给父会话宿主，限当前 Windows 用户验证及登录 localhost。源码、日志、命令行、备份和问题包均不包含明文凭据。

主控和原生宿主的轮转日志位于 `debug/desktop-session/`，通过连接关联 ID、任务 UUID、PID 和 Windows 会话 ID 对照。环境检查参考 BetterGI 的原生组件与服务诊断。分身入口只读取必要系统配置，家庭版通过同样的白名单后才尝试连接。

## VM 验收

在 VM-win11 中使用 `uv sync --locked --group dev` 和项目的 Electron 开发启动流程。SSH 用于部署、启动交互式验收程序和取证。通过 VM 已登录的父桌面输入 Windows 密码，使用独立的 BitBlt 与 RapidOCR 探针在 WTS 确认的子会话验证实际画面。记录任务随会话运行、调度状态、停止收尾、历史恢复、分辨率、两种最小化和注销。家庭版、实体显示器断电、宿主断开和各上游游戏应独立记录实测范围。

本次 VM 验证中，通用托管探针由分身设置直接启动时记录到会话 2，通过分身队列启动时记录到会话 5，从首页快速开始启动同一队列时记录到会话 1。主窗口进入原有调度页，停止按钮将分身任务标记为已取消。子执行器释放写锁后，主后端恢复到就绪状态，历史搜索可见被中止的探针记录。关闭分身时显示状态并完成注销。后台最小化、原生最小化及恢复可见后分别通过独立 BitBlt 探针验证。每组 12 张截图均为 1920×1080，RapidOCR 分别识别出 12 个不同的标记。播放测试音时，预览宿主检测到一个音频会话，并将其音量从 0 调整到 37。

管理员权限复测中，交互式 Electron 主进程、子会话执行器与 BetterGI 均持有提升后的令牌。执行器临时计划任务使用最高可用权限；普通权限任务曾在跟踪已提权的 BetterGI 时收到 `OpenProcess` 拒绝访问。修复后，从分身设置启动「新 BetterGI 托管」在子会话 6 显示 BetterGI 0.67.0 窗口；BGI 提示没有找到原神安装路径，符合该 VM 未安装游戏的前置条件。此结果仅证明 BGI 在子会话启动及进入其原有游戏检查流程。
