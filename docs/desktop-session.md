# 桌面分身

「设置 → 桌面分身」提供独立的队列和托管任务选择，以及手动启动入口。分身连接后由主会话中的 MAS 派发所选任务。支持 PC 通用托管、BetterGI、ok-ww、ok-nte、绝区零一条龙、奇想盒，以及仅包含这些托管的队列。模拟器托管在主会话运行。BetterGI 需关闭接管更新。启用额外提权的 BetterGI、奇想盒以及绝区零一条龙需以管理员身份启动 MAS。分身内可运行队列和账号前后置命令、通过 URL 或可执行文件启动游戏，以及追踪脚本进程。绝区零一条龙在分身中会跳过任务完成后的关机。留空时只显示子桌面。主页快速开始仍在主会话启动。分身任务可在同一个调度页监控和停止。配置了完成后电源操作的队列需要先改为「无操作」。

## 实现路径

1. Electron 的 `desktopSessionHandlers` 校验来自 MAS 窗口的 IPC，在独立 Vue 窗口显示控制栏。它将预览区的坐标换成物理像素，交给父会话的 Python 宿主。
2. `app.core.desktop_session.host` 通过 ATL 的 `AtlAxCreateControlEx` 承载系统 `mstscax.dll`。ActiveX 使用 localhost、CredSSP、固定子桌面尺寸及 SmartSizing。预览嵌入 Electron 客户区。后台最小化将预览移到屏幕范围外，原生最小化随 Electron 窗口最小化。
3. BetterGI、ok-ww、ok-nte 的原有账号切换流程和 ok 系列的游戏启动器交互在分身执行器内运行，保留调度台的执行进度。
4. 登录后用 WTS 确认子会话。主 MAS 按原先的调度流程持有配置锁、创建任务并保存历史。任务内的进程操作使用子会话范围，普通任务仍在主会话。
5. 需要启动命令、脚本或游戏时，任务计划程序在指定子会话用 `pythonw.exe` 启动一个进程执行器。通过核验 PID、会话与账户的本机命名管道发送启动参数。执行器在 Windows Job Object 中监督本次启动的进程树。停止任务、工作进程退出或控制管道断开时，执行器收尾。
6. 主 MAS 持续提供原有 HTTP 与 WebSocket。关闭分身时，主 MAS 先停止分身任务并等待收尾，再注销子会话。主后端在分身任务前后使用同一进程与地址。

## 凭据和诊断

输入的密码通过本机验证，并确认属于当前用户后保存 `config/desktop-session/credentials.json`。该文件以 Windows 账户为键，值是 DPAPI-NG `LOCAL=user` 密文的 Base64。密码经 Electron 的私有进程管道交给父会话宿主，限当前 Windows 用户验证及登录 localhost。源码、日志、命令行、备份和问题包均不包含明文凭据。

主控和原生宿主的轮转日志位于 `debug/desktop-session/`，通过连接关联 ID、任务 UUID、PID 和 Windows 会话 ID 对照。环境检查参考 BetterGI 的原生组件与服务诊断。分身入口只读取必要系统配置，家庭版通过同样的白名单后才尝试连接。

原生宿主每次检测环境或开始连接时，记录 Windows 版本、版别（EditionID）、发布版本、系统构建号及修订号，并保留系统架构、Python 版本和位数、进程是否已提权等诊断信息。版本信息只写入本地分身日志。

打开桌面分身窗口时自动执行只读环境检查。检测异常时，点击「尝试修复环境」可查看改动清单和启用 RDP 的影响，确认后才请求管理员权限并备份原设置。系统环境复查通过后保留修复结果，再验证账号和尝试连接。修复或复查失败时恢复原设置，已启动的远程桌面服务继续运行。密码错误时可重新输入。若有权限读取 Windows 安全日志且找到与本次登录匹配的事件 4625，窗口会显示事件时间和状态码。环境复查失败时可导出分身日志。家庭版兼容性提示来自原生连接失败后的诊断，无需更改系统版本。组策略、系统组件和端口问题见[环境修复指南](desktop-session-troubleshooting.md)。

## VM 验收

在 VM-win11 中使用 `uv sync --locked --group dev` 和项目的 Electron 开发启动流程。SSH 用于部署、启动交互式验收程序和取证。通过 VM 已登录的父桌面输入 Windows 密码，使用独立的 BitBlt 与 RapidOCR 探针在 WTS 确认的子会话验证实际画面。记录任务随会话运行、调度状态、停止收尾、历史恢复、分辨率、两种最小化和注销。家庭版、实体显示器断电、宿主断开和各上游游戏应独立记录实测范围。

从主后端的分身派发入口启动通用托管，记录脚本和本机游戏进程所在会话、主后端 PID 和任务状态。停止后检查脚本与游戏退出、任务终态及主后端持续就绪。只开展探针验证时，证据范围限于通用托管链路。
