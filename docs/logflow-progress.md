本轮补充实现已通过采集会话、插件生命周期及观察 API 回归。观察额度用尽后会对已接纳节点归并并标记不完整。LogFlow 的单行、多行、上报、观察和后置归并统一使用结构化状态。默认报告省略进行中的节点。专项迁移时按 LogFlow 契约声明状态与报告策略。

独立审核复核后，已修复原生监控的启动偏移、尾行和停滞回调，隔离文件读取缺口，补齐结构化凭据过滤，纠正 worker 工作目录、Windows 回收期限及暂停时的上报行为。采集进程可以加载插件的原生扩展模块。多代轮转和等长改写受通用文件身份与偏移的检测范围限制。

PR 复审补齐了超时后的回收。Windows 回收线程排队超过期限时，会话先交付不完整报告，待后台确认进程退出后自动释放 Job 并清除待确认登记。

新一轮独立审核验证了通知接管前可重试、句柄关闭异常仍交付报告、自定义来源超长行后继续采集，以及容量满后撤回同步到宿主与结束报告。

## 接下来按验收拆分的开发步骤

| 顺序 | 交付项 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| 1 | 默认 Flow 模拟闭环 | 一份节点声明绑定真实 MAS 日志监控器；隔离 worker 解析；调用侧和 MAS 读取同一批运行期节点；逐条、汇总与关闭通知分别验证 | 已通过模拟验收。本地 SDK wheel 经实际调度验证 stdout、原生文件和主动上报。正常结束和取消时，HTTP 补读与 Notify 均包含监控停止前写入的完整尾行 |
| 2 | 可替换的处理环节与依赖收口 | 单独替换一个处理器，来源、观察与报告无需改动；将阻碍扩展的旧类型移出核心，核对旧报告兼容 | 已通过模拟验收。日志条目和前后置处理签名由共享模块持有，旧包与 SDK 导出同一契约，42 组旧报告输出逐项一致 |
| 3 | 自定义组合与协议来源 | 内置文件、MAS 和主动上报可以独立选择；验证混合来源归属、背压和关闭；发布 SDK 的来源、处理器和 sink 入口 | 内置组合、Python 上报及自定义 Source/Processor/Sink 已验证。原生文件和进程日志均验证了有限尾部排空，进程输出超长行按整行丢弃。自采集文件单行超限时，混合会话仍能收齐主动上报并标记不完整。保留外部进程主动上报的扩展方向 |
| 4 | 插件宿主、节点语义与实时查询 | 独立模拟插件验证声明注册、停用、重载和在途会话；节点类型、附加数据、修订/撤回及可调用查询接口 | 已验证声明注册、按来源修订、游标隔离、终态缓存淘汰和过期。停用与重载会并行收尾同一实例的多个会话，慢 sink 独立超时；启动取消和退出待确认时保留进程登记。正式 UI 归入未来需求 |
| 5 | 正式通知桥接 | 采集和通知独立开关，逐条/汇总沿用旧口径；超时标明不完整，重复收尾不重发；经 Notify 投递到测试传输端 | 模拟插件已验证独立开关和恢复原排版。全成功及混合成败报告按托管未完成数过滤失败详情；收尾异常或超时时保留已采集内容。真实渠道和持久化配置升级随专项迁移验证 |
| 6 | 按插件逐个迁移 | 对应专项先插件化，再做实跑对照并切换。覆盖重试、账号归属、时间戳和真实通知 | 已模拟对照 ZZZ-OD 多账号报告、BAAH 轮转、BetterGI 双阶段和独立统计、MaaEnd 跨阶段修订与排序。OK-NTE 已对照调度取消、剩余体力及两种排版，OK-NTE 和 BAAH 均对照了跨分钟收尾。专项实机由维护者在插件迁移时验证 |
| 7 | 预算与旧入口验收 | 根据实测定容量、时限并跑完整回归；最后一个调用方迁走后才清理旧入口 | 四会话三来源模拟运行 180 秒，24 次轮转后各收齐 2,161 条节点，慢 sink 超时与其余会话隔离。条数或字节超限时保留已交付节点，归并超限时按声明顺序生成不完整报告。后端 559 通过、1 跳过、3 子测试通过，最近一次前端验证 205 通过。生产长跑、预算校准及迁移后旧入口清理待做 |

## 正式迁移仍需的证据

截至上游 `281062e96`，BAAH、MaaEnd、OK-NTE、OK-WW 和 ZZZ-OD 共七处直接构造旧管线。当前分支的内置任务没有调用 LogFlow 入口。专项完成插件化后，可用同一份实际账号配置生成旧报告和 LogFlow 报告作对照。正式通知只由一条路径投递。

| 接入方 | 迁移时核对 |
| --- | --- |
| General | WebUI 保存的规则与 Hook 按本次运行取值，时间前缀、窗口收尾及两种通知模式沿用现有配置 |
| OK-NTE | 实际脚本取消时能补读收尾日志，剩余体力和逐条时间正确，通知只投递一次 |
| OK-WW | 在真实切号中核对批次账号归属、补跑覆盖和各账号报告，保留单账号路径 |
| BAAH | 真实日志轮转和日期切换后跟上末尾，保持嵌套节点归并及报告归属 |
| ZZZ-OD | 真实多实例下，运行中节点和最终报告都归属于正确账号，警告与补跑按现有口径展示 |
| MaaEnd | 真实多阶段执行覆盖穿插重试、同名多实例、日志时间失效时的回退，以及材料与统计的独立通知 |
| BetterGI | 实际双阶段分步表保留重试选轮，节点关闭时分步与掉落统计仍独立交付 |

联调可使用本地 SDK wheel，发布前再用实际配套的 SDK 发行包验收。迁移时记录宿主与插件版本、实时节点和最终报告对照、原配置升级结果，以及实际并发和收尾耗时。五个旧调用方全部迁移并完成外部兼容复核后，才进入移除旧包的全量回归。
