## 接下来按验收拆分的开发步骤

| 顺序 | 交付项 | 通过条件 | 状态 |
| --- | --- | --- | --- |
| 1 | 默认 Flow 模拟闭环 | 一份节点声明绑定真实 MAS 日志监控器；隔离 worker 解析；调用侧和 MAS 读取同一批运行期节点；逐条、汇总与关闭通知分别验证 | 已通过模拟验收。本地 SDK wheel 经实际调度验证 stdout、原生文件和主动上报。正常结束和取消时，HTTP 补读与 Notify 均包含监控停止前写入的完整尾行 |
| 2 | 可替换的处理环节与依赖收口 | 单独替换一个处理器，来源、观察与报告无需改动；将阻碍扩展的旧类型移出核心，核对旧报告兼容 | 已通过模拟验收。日志条目和前后置处理签名由共享模块持有，旧包与 SDK 导出同一契约，42 组旧报告输出逐项一致 |
| 3 | 自定义组合与协议来源 | 内置文件、MAS 和主动上报可以独立选择；验证混合来源归属、背压和关闭；发布 SDK 的来源、处理器和 sink 入口 | 内置组合、Python 上报及自定义 Source/Processor/Sink 已验证。原生文件和进程日志均验证了有限尾部排空，进程输出超长行按整行丢弃。自采集文件单行超限时，混合会话仍能收齐主动上报并标记不完整。保留外部进程主动上报的扩展方向 |
| 4 | 插件宿主、节点语义与实时查询 | 独立模拟插件验证声明注册、停用、重载和在途会话；节点类型、附加数据、修订/撤回及可调用查询接口 | 已验证模拟声明、停用、重载、按来源修订，以及同一托管重复执行时的游标隔离。终态补读已覆盖节点缓存容量淘汰和过期。启动重复取消时保留在途 worker 登记。正式 UI 归入未来需求 |
| 5 | 正式通知桥接 | 采集和通知独立开关，逐条/汇总沿用旧口径；超时标明不完整，重复收尾不重发；经 Notify 投递到测试传输端 | 模拟插件已验证独立开关和恢复原排版。全成功及混合成败报告按托管未完成数过滤失败详情；收尾异常或超时时保留已采集内容。真实渠道和持久化配置升级随专项迁移验证 |
| 6 | 按插件逐个迁移 | 对应专项先插件化，再做实跑对照并切换。覆盖重试、账号归属、时间戳和真实通知 | 已模拟对照 ZZZ-OD 多账号报告、BAAH 轮转、BetterGI 双阶段和独立统计、MaaEnd 跨阶段的实时修订与材料统计，以及 OK-NTE、BAAH 跨分钟收尾的时间显示。专项实机由维护者在插件迁移时验证 |
| 7 | 预算与旧入口验收 | 根据实测定容量、时限并跑完整回归；最后一个调用方迁走后才清理旧入口 | 四会话三来源模拟运行 180 秒，24 次轮转后各收齐 2,161 条节点，慢 sink 超时与其余会话隔离。达到节点容量后，即使自定义 sink 清理抛错也保留已交付节点和容量不足原因。后端 554 通过、1 跳过、3 子测试通过，最近一次前端验证 205 通过。生产长跑、预算校准及迁移后旧入口清理待做 |
