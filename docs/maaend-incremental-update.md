# MaaEnd 的两条增量更新路径

更新方式仍默认“全量更新”。选择“增量更新”后，MAS 按下面的顺序尝试：

**GitHub 官方 ZIP 按需读取 → Action 自建站增量包 → 原来的全量下载。**

没有 CDK 也可以使用两条增量路径。全量回退沿用原有来源选择，有 CDK 时可使用 Mirror 酱。
停止更新会正常取消，不会因为取消而继续下载备用包或全量包。

## 两条路径的覆盖范围不同

| 项目 | GitHub 按需读取 | Action 自建站备用包 |
| --- | --- | --- |
| 起始版本 | 不限制版本跨度，有可信缓存即可尝试 | 正式目标只覆盖之前最近三个正式版 |
| beta | 可直接比较当前缓存 beta 和目标 beta，无需逐版升级 | 必须有与目标 beta 同号的正式版基准 |
| 例子 | 旧正式版或 b4 可尝试直接重建 b8 | `3.0.0 / 2.9.0 / 2.8.0 → 3.1.0`；`3.1.0 / 3.1.0b4 → 3.1.0b8` |
| 更早的版本 | 按差异量判断是否值得尝试 | 例如 `2.7.0 → 3.1.0`、`3.0.0 → 3.1.0b8` 使用全量 |
| 没有同号正式版 | 不影响 GitHub 比较 | 例如没有 `3.2.0` 正式版时，`3.2.0b1 → b8` 的备用增量不可用 |
| 额外条件 | 官方下载地址必须支持 HTTP Range | 必须有精确匹配目标及本地正式基准的已发布增量包 |

beta 通道允许用户从 `3.1.0` 正式版切换到 `3.1.0-beta.N`。
这遵循用户选择的通道，不将同号 beta 自动当成无需更新。

## 差异量限制与回退

GitHub 路径复用 MFW 的 Range 读取器，但重建的是原始 ZIP，不是 MFW 的文件树。
请求只接受范围正确、长度完整的 `206 Partial Content`，服务器返回 `200` 时立即放弃区间读取。

- 实际累计读取超过官方整包 **40%**，或变化条目超过 **3000**，放弃 GitHub 区间路径。
- 读取量包含 ZIP 头、中央目录和区间块对齐的开销，并不只等于变化文件的大小。
- 单次网络读取超时为 30 秒。配置了 CDK、可回退 Mirror 酱时，复用 MFW 网速保护：
  用整包 40% 的保守读取上界估算，预计网络时间超过 120 秒或实际网络时间超过 180 秒即放弃。
  没有较快的完整包备用源时，不用这两个时间阈值打断仍在传输的慢速直连。
- 自建站包最多 32 MiB，清单最多 512 KiB；过大、不省流量或无法验证的包不会发布。
- 任何一路遇到不匹配、损坏、超时或不支持的格式都会丢弃该路未完成的 ZIP，再尝试下一路。

## 为什么可以跳过 beta，以及如何处理删除和重复内容

MAS 不把“正式版到 b8”的补丁直接覆盖到 b4 的目录。GitHub 路径从缓存 ZIP 复用一致的原始压缩数据，
取回目标版本的变化数据、文件头和中央目录，重建完整的目标 ZIP。已经一致的数据可以复用；
重命名、删除、内容回退和新增文件以目标 ZIP 为准，不需要累加 b5、b6、b7 的补丁。

Action 的 beta 备用包以同号正式 ZIP 为固定基准。安装 b4 之后仍保留该正式基准，
下次可从它直接重建 b8，再交给原有事务安装器切换完整版本。已被官方删除的文件不会通过旧目录叠加而残留；
用户配置等受保护文件继续沿用原有保留规则。

## SHA256 与缓存要求

CRC32、大小及压缩方式只用于判断哪些旧数据值得尝试复用，不能代替完整性校验。
重建完成后，ZIP 大小与 SHA256 必须和 **从 GitHub 官方发行页独立取得的整包记录**完全一致。
即使文件内容相同，压缩字节不同也可能无法通过；这时使用备用路径或全量，不放宽校验。
自建站清单不能改写官方校验依据，成功才允许进入安装器。

只在增量模式安装成功后缓存原始 ZIP：最多一份最近安装归档和一份最近正式基准。
两份可能占用约两个完整压缩包的磁盘空间；这不是解压后的安装备份。
首次使用、以前一直选全量、缓存损坏或原生更新导致没有适用基准时，可能需要先全量一次。
不会为了建立增量基准而另下一个大包。只有 beta 缓存、没有同号正式基准时，GitHub 仍可尝试；
Action 备用增量不可用时全量。

## 发布与验证边界

Action 位于 `AUTO-MAS-Copilot-Data`，从官方分页发行记录自动选择起点；
正式版的多个起点共享去重后的新增字节池，每个计划发布前都重建并验证目标整包。
客户端与 Action 必须同时支持 v2；旧客户端不认识新包时全量，新客户端不接受没有范围信息的旧 v1 发布包。

已用真实官方 x64 `v3.1.0-beta.4 → beta.5` 验证完整 ZIP 重建，整包 316,003,772 字节，
原型实际从 GitHub 读取 38,917,565 字节，SHA256 与官方记录完全相同。
这证明字节重建能力，不表示 Action 会绕过“同号正式基准”的发布限制。
真实验证在临时目录进行，不启动游戏，不改用户安装。arm64 和正式站点发布另行验收。
