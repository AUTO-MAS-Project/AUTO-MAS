# MaaEnd 增量更新机制

MaaEnd 更新方式默认仍为「全量更新」。切换为「增量更新」后，MAS 按以下优先级依次尝试：

**GitHub 官方 ZIP 按需读取 → Action 自建站增量包 → 原全量下载（有 CDK 时走 Mirror 酱）**

两条增量路径均无需 CDK；用户手动停止更新会直接取消，不会触发备用包或全量回退。

## 两条增量路径对比

| 维度 | GitHub 官方 ZIP 按需读取 | Action 自建站增量包 |
| --- | --- | --- |
| 起始版本 | 不限跨度，有可信本地缓存 ZIP 即可尝试 | 正式目标仅覆盖前最近 3 个正式版 |
| beta 支持 | 可直接从旧正式版或旧 beta 重建目标 beta | 必须具备与目标 beta 同号的正式版基准 |
| 示例 | 旧正式版或 `b4` 直接重建 `b8` | `3.0.0 / 2.9.0 / 2.8.0 → 3.1.0`；`3.1.0 / 3.1.0b4 → 3.1.0b8` |
| 不适用情形 | 官方下载地址不支持 HTTP Range，或差异超阈值 | 无同号正式基准（如无 `3.2.0` 时 `3.2.0b1 → b8`）或更早版本 |

> 选择 beta 通道时允许从同号正式版（如 `3.1.0`）切换至 `3.1.0-beta.N`，遵循用户通道选择。

## 差异阈值与回退规则

- **Range 校验**：复用 MFW 的 Range 读取器重建完整原始 ZIP，仅接受范围精确的 `206 Partial Content`（返回 `200` 立即放弃）。
- **流量与条目上限**：累计读取量超过整包 **40%**（含 ZIP 头、中央目录与块对齐开销）或变化条目超过 **3000** 时放弃 GitHub 路径。
- **超时与慢速保护**：单次读取超时 30 秒；若已配置 CDK 可回退 Mirror 酱，预计耗时超 120 秒或实际耗时超 180 秒时放弃直连。无更快备用源时不主动打断慢速直连。
- **自建站包限制**：单个增量包上限 32 MiB，清单上限 512 KiB。
- **失败清理**：任一路出现不匹配、损坏或超时都会丢弃未完成的临时 ZIP，再顺延尝试下一路。

## 重建原理与完整性校验

- **整包重建而非目录覆写**：两种路径均从本地缓存 ZIP 复用一致的压缩数据并补齐变化部分，重建出**完整的目标版本 ZIP** 后再交给原有事务安装器切换，因此跳过中间 beta 不会残留已删除文件，且受保护的用户配置继续保留。
- **严格 SHA-256 校验**：CRC32 与大小仅用于筛选可复用块；重建后的 ZIP 大小和 SHA-256 必须与**从 GitHub 官方发行页独立获取的整包记录**完全一致，不通过即回退下一路，绝不放宽校验。
- **本地缓存策略**：仅在增量模式安装成功后缓存原始 ZIP，最多保留「最近一次安装归档」与「最近一份正式基准」（约占两个完整压缩包空间）。首次使用或缺少有效基准时自动走一次全量安装建立缓存。

## 服务端与协议版本

自建站增量包由独立仓库 `Auto-Mas-Updater-ReleaseOTA` 的 Action 生成并预验整包 SHA-256。客户端与 Action 统一使用 v2 协议（不兼容无范围信息的旧 v1 包）。
