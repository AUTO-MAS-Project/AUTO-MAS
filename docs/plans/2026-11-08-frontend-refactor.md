# 前端渐进重构落地方案

## 目标与基线

从最新 `origin/dev`（`9aab1ff2b610be534a32d17a9a136acb01715398`）开始，减少新增专项时的重复登记，并为后续编辑器拆分建立可执行的尺寸约束。此次先完成登记、路由、门禁和行为验证的完整闭环，不全量重写前端。

原 `fix/settings-appearance-hierarchy` 分支及其提交保留；3 个未提交文件已存入 `codex: preserve settings notification WIP before frontend refactor 20261108` stash，不混入重构。

基线为 335 个 Vue 文件，52 个超过 500 行、14 个超过 1000 行。路由包含 33 条普通专项入口、12 条 MFW 家族入口和 1 条 MAA 养成入口。行数是调查指标，不是重构收益或完成标准。

## 设计决策

- 静态资料放在低层 `utils/scriptMetadata.ts`，只依赖类型和图片资源。图标、展示名、标签颜色、新建卡片及路由后缀在此登记；不得导入 API、页面或 MFW composable，避免循环依赖。
- 保留现有 `SCRIPT_LOGOS` / `SCRIPT_LABELS` 消费接口，由资料表生成投影，并保留原枚举顺序。MFW flavor 读取公共资料，但继续持有引导、插槽、托管任务及页面差异。
- 页面懒加载登记与路由生成属于 `router/scriptEditorRoutes.ts`。普通专项生成脚本编辑、用户新增、用户编辑三种入口；MFW 继续使用原四种入口与 canonical 修正；养成入口显式保留。
- 保持路径、路由名、参数、标题、创建卡片顺序、搜索别名和创建后的 history state。类型完整性与真实路由解析共同验证，不能只看 typecheck。
- 保留 `screen_view` 和脚本创建的原结果所有者，不增加点击级事件，不放宽分析事件的有限类型白名单。
- 不合并不同保存契约，不修改后端 schema、生成客户端、上游脚本格式或用户数据。

## 实施单元

### U1：逐文件尺寸门禁

增强现有 `audit-baseline.mjs`，保留两种报告模式，增加 `--check <base-ref>`：新增组件及原不超过 500 行的组件最终不得超过 500；原超限组件不得增长；Git 识别的重命名沿用旧基线，删除不产生配额。CI 使用 PR 事件的精确 base SHA，不使用会移动的 dev；本地和 CI 复用 Node 内建测试。

新增业务是否必须先提取职责仍由代码审查判断；机器门禁只验证尺寸必要条件。未暂存的超限文件搬迁可能被当作新增，文档说明该限制，不操作使用者索引。

文件：`frontend/scripts/audit-baseline.mjs`、`audit-baseline.check.mjs` Node 测试、`frontend/AUDITING.md`、`format-check.yml`。

验证：临时 Git 仓库覆盖 500/501 行、新增、存量增长、删除、重命名、未跟踪文件、换行与非法基线；运行本仓库基线检查。

### U2：静态专项资料收口

迁移图标、展示名、标签色、新建卡片与路由后缀；MFW 描述继续持有领域差异。资料表满足全部生成的 `ScriptType`，新建卡片保持旧排序。删除已经被表替代的重复资料，不增加通用能力开关。

文件：新增静态资料表、`scriptLogos.ts`、`scriptCreateFlow.ts`、`scriptListPresentation.ts`、三个 MFW flavor 描述及相关契约测试。

验证：迁移前记录并验证卡片顺序和搜索行为，迁移后复跑；检查低层资料没有运行时副作用与环形依赖。

### U3：路由生成与所有跳转接入

集中懒加载页面登记，生成普通专项三种入口。脚本列表的编辑脚本、新增用户、编辑用户和创建流程统一使用具名路由目标；MFW 创建后仍进入 setup，附带 `scriptData` 的 history state 保留。路由分析从真实登记的页面种类读取，沿用原事件语义。

文件：`router/scriptEditorRoutes.ts`、`router/index.ts`、`router/analytics.ts`、`Scripts.vue`、`useScriptCreation.ts` 及路由契约测试。

验证：使用实际 Vue Router 内存路由解析全部旧入口，确认名称、参数、URL、标题、唯一性、MFW canonical 的 query/hash 和养成 props。构建验证真实懒加载模块可解析。

### U4：用户路径与集成验收

复用隔离 E2E 启动器，为从新建卡片到脚本编辑、从脚本列表到用户新增与编辑补代表性行为断言；检查刷新后的保存结果。复用现有配置来源卡片与养成流程验证特殊入口，避免重复铺整站截图。

验证顺序：相关契约测试 → 尺寸检查 → 全量 lint、typecheck、format、词表检查 → 构建 → 最小相关隔离 E2E。执行结果写入独立验证记录，不把未运行项描述成通过。

## 存量编辑器与样式的后续迁移方式

后续每次以一个实际修改的页面为单位，先读取保存与生命周期契约，再提取具有明确状态所有权的业务区域。不得把整页 script 搬进 composable 充当拆分。新增业务按项目组件尺寸政策先提取受影响职责；维护不扩张尺寸。

保存契约至少区分普通脚本字段补丁、普通用户字段、MAA 草稿/失败回读、HSR 共享与独立配置归属、MFW 逐笔保存与失败记账。不能以“只剩一种实现”为验收标准。仅当两个真实消费者语义一致时才抽共享机制，并保持顺序、失败后继续、草稿与离开保护。

样式随受影响区域迁移到现有 Ant Design token、`useTheme` 和共享 surface 规则；对应页面验证明暗主题、自定义背景及窄窗口。先复用现有原语，不引入 Storybook、Stylelint、新 UI 库或动态表单框架。装饰组件和全量重复率清理不进入本轮。
