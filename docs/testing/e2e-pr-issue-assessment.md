查询日期：2026-10-08。调研窗口为 2026-04-08 至 2026-10-08，重点抽取近期与调度、账号、模拟器、游戏任务相关的代表样本；这不是该窗口内全部 Issue/PR 的清点。PR 合并日期按 GitHub UTC 记录。每个 GitHub 结论均链接到一手记录。Runner 适配判断对照本仓库的[当前 E2E 流程清单](./e2e.md)。

## 结论

本次 E2E 框架的价值不在于“跑一次就证明一个 PR 完全正确”，而在于把 PR 对应的用户路径变成可重复、可选跑、带证据的检查。一次通过只能证明指定 commit、配置、账号、脚本和环境下的已覆盖断言成立；一次失败能证明该路径违反断言，但不能自动证明代码改动是根因。用同环境对照 base/head、控制外部因素并保存请求、调度事件、阶段日志和截图，才能把失败更可靠地归到某一层。

## 证明 PR 正确/错误的判读标准

- **能证明的范围：** 指定 SHA、工作区差异、配置、脚本/账号、环境下，某个用户路径达到或违反了具体断言。例如“所选用户范围正确进入启动请求”“任务重试三次时前置脚本只运行一次”“MuMu 关机后等待到稳定离线再重开”。
- **失败不能直接归罪于 PR：** 真实运行失败也可能来自模拟器、网络、账号登录态、游戏更新、脚本上游或机器状态。按证据先标失败阶段，再检查对应日志/请求/WS 事件；基线和 PR commit 在同一环境对照，才有较强的回归归因。
- **通过不能证明整个 PR 正确：** 只覆盖断言涉及的用户路径。正常成功路径不能证明异常、重试、取消、多用户、超时和跨时区分支。
- **一次运行可缩小根因，不保证唯一根因：** 记录 screenshot、请求体、调度状态、公开任务结果与阶段日志，可以定位前端、调度、配置、模拟器或脚本边界；确切代码根因仍需要源码追踪和确定性专项/单元测试。对于游戏执行，只使用 MAS 与脚本公开契约，不推断上游私有状态。

每次 PR 验证至少记录场景、命令、完整 commit SHA、工作区 dirty 状态、前置条件、实际断言、结果、证据路径和未覆盖范围。真实测试的完整 HTML、终端输出、原始日志可能包含本机信息；只挑选并人工检查脱敏截图和摘要附到 PR。
