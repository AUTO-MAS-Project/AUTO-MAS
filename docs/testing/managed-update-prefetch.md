# 托管更新预下载接入核对

本次目标是为下一阶段调度提供依据：前一脚本运行时，只提前下载后一脚本的更新；安装和版本切换仍须等待安装目录空闲。本次不新增队列调度、自动预下载或后台常驻任务。

核对基线：AUTO-MAS dev bba243a7，BetterGI PR #1821 的 0bfa235f，以及本次 SRC、BAAH 独立 PR。ok 系列继续由 pyappify 处理，绝区零一条龙继续使用原生启动器。

| 奇想盒后端 | 是，统一下载器、异步 pip 子进程、哈希工作线程 | wheel 下载后还需 `pip wheel` 准备依赖，再离线安装；总入口先要求进程退出且临时依赖目录随函数退出删除 | 把 wheel 和依赖准备保留为可消费的候选；安装时才检查空闲并写 pending，不能只缓存主 wheel 就宣称整个更新已下载 |
| SRC | 是，异步 Git 子进程；更新/安装取消时等待写盘结束 | 本次 `prepare_update` 在独立对象库下载，`apply_update` 在原安装空闲后导入并快进 | 可预取代码对象；依赖、app.asar、ADB 仍由原生安装器在启动前处理，尚不具备全部依赖离线安装能力；Git 传输不走 FluxDown |
| BAAH | 是，统一下载器与可等待取消的校验/安装工作线程 | 本次 `prepare_update` 下载并校验官方 ZIP；`apply_update` 持锁后复核安装身份，再可恢复地切换目录 | 已提供两阶段入口；上层调度需管理候选归属、配置代次、去重、超时与缓存回收，不能绕开安装锁或将下载完成视为安装完成 |

“网络异步”只表示不直接阻塞事件循环，不表示已经完成调度接入，也不表示总入口允许在脚本运行时调用。

## 调度接入契约

1. 调度项保存脚本/引擎类型和配置代次；开始下载前冻结通道、来源、凭据与代理。不要保存正在运行的协程或依赖可变配置对象决定后续来源。凭据不写日志、任务标识或缓存清单。
2. 下载只写 MAS 缓存；同一个物理安装目录仍由安装/运行占用约束串行。安装锁不得覆盖提前下载阶段，也不能为了下载而停掉当前脚本。
3. 候选包含目标身份、包体/对象位置与完整性依据。应用前重新检查安装目录、当前版本或提交、配置代次和候选摘要；原生更新或用户更改配置后丢弃过期候选，不能盲目安装旧包。
4. 预下载失败只影响该预取结果；轮到脚本时仍按既有更新/安全回退策略判断。取消下载不允许偷偷进入安装；未确认停止的下载器保留独立目标，避免删掉仍有写入者的文件。
5. 安装一旦开始，持有占用直到文件写入、原生安装器或回滚真正结束。安装未确认不允许启动；不要把“下载成功”“任务受理”记成“更新成功”。
6. MAA 全局缓存、MFW 谱系缓存和单安装候选不是同一个去重粒度。调度器需区分下载共享与安装占用，并在退出/取消时收回现有自建后台任务。

## 已验证范围

SRC 使用本地 Git 仓库替代远端传输，验证预取不改原工作区、应用快进并调用原生安装器、本地修改使候选失效、安装失败保留标记并恢复部署设置、取消等待写盘结束。

BAAH 使用官方 ZIP 结构的最小夹具，验证持有安装占用时仍可预下载、应用保留用户配置、应用前重新校验包体、原生修改使候选失效、拒绝更新包覆盖用户配置、取消下载不改原安装。

尚未验证 Windows 上的真实 SRC 原生依赖安装、BAAH 发行包升级与真实账号任务；本次也未宣称其他适配器已经完成两阶段改造。
