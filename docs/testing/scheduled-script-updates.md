# 顺序队列更新编排

脚本开启原有更新托管后，首项仍由自己的启动前流程更新并安装。队列仅在当前账号收到脚本内首个成功任务节点、经过 60 秒且仍在正常运行时，通过 `run_script_update` 调用下一项管理器的 `prefetch_script_update`。不以启动、登录计时或账号整轮完成替代节点完成。

后台预取只允许写 MAS 下载缓存。当前项完成收尾后等待已启动的下载收敛，再由下一项原有的安装锁、校验、安装与失败回退流程消费候选。没有收到节点结果或脚本在保护窗口内结束时，撤销计时器，下一项启动前照常更新。切号、重试、失败及停止时取消预取并等待下载收尾，避免进入下一次登录时下载仍在抢占网络。

普通队列与循环队列共用该入口；循环只预取当前轮已到期的下一项。运行周几不匹配、没有选中账号和已删除的条目不预取。预取后脚本配置或全局更新配置变化时，丢弃候选并重建管理器。所有配置仅在内存比较，不写入日志、缓存标识和遥测。

| 更新对象 | 预下载内容 | 应用边界 |
| --- | --- | --- |
| MAA GitHub 本体及资源 | 独立缓存内的官方 OTA 或完整包及资源 staging | 复核原版本、包摘要后复制并登记，原生更新器安装；资源启动前才分发 |
| MAA Mirror 本体及资源 | 已有共享完整包及资源 staging | 启动前才登记和分发，预取不分发任何实例 |
| MaaEnd | 官方完整 ZIP 及 SHA256 校验 | 复核安装版本/架构，原有可恢复目录切换 |
| HSR M7A／SRA | 每引擎独立缓存包 | 复核安装版本和包摘要，原有进程门及安装/回滚 |
| MaaFW／M9A／MSS | 完整包进入核心共享下载缓存 | 基线未变时复用候选，变化后重新发现；保留预检、载荷登记及视图切换 |
| 奇想盒 | 官方后端 wheel 及隔离构建的全部依赖 wheel | 复核安装版本及所有包摘要，原有离线安装和恢复标记 |

奇想盒目前没有运行中可用的首节点完成结果，作为前项时不会触发后台预取；作为后项可提前准备更新。其它未提供可靠节点完成结果的适配器同样保持启动前更新，不推断首节点结果。

## 正在修改的 PR 的接入位置

以下三个 PR 保持独立，不导入、复制或合并其尚在修改的实现。共同接缝是管理器的 `prefetch_script_update()` 与 `discard_prefetched_update()`，默认实现不执行下载。合入后按下表接入；安装继续放在原启动前入口，不能在预取钩子调用整个 `prepare()`。

| PR | 预取钩子 | 安装消费 |
| --- | --- | --- |
| #1821 BetterGI | 拆出官方安装器下载及校验，保存候选 | 进程空闲后调用官方安装器；运行期通知覆盖不提前写 |
| #1822 SRC | 调用其 `prepare_update` 保存 Git 对象候选 | 启动前调用 `apply_update`；依赖与 app.asar 仍交原生安装器 |
| #1823 BAAH | 调用其 `prepare_update` 保存官方 ZIP 候选 | 启动前调用 `apply_update`，保留安装身份复核 |

候选取消、配置变化和未消费时由 `discard_prefetched_update()` 回收；尚未确认停止的下载器必须保留自己的独立下载目标。公共队列不提前占用安装、不调用游戏任务，也不宣称这三个 PR 已接入。

## 验证

`tests/core/test_script_update_queue.py` 验证 60 秒保护窗口、没有成功信号时不预取、短任务撤销计时器、正常完成等待下载、切号/重试/失败/停止等待清理，以及预取失败不影响当前脚本。专项更新回归继续守护各自的安装和恢复边界。

真实 Windows 发行包更新、真实账号任务、登录网络竞争与同组多实例需要作者本机验证；自动测试不替代这些证据。预取不新增遥测事件，脚本及队列终态继续由原观察者记录。
