# 插件化迁移计划

## 目标

以 `dev` 为基线，将插件框架、MUMU 模拟器和 MAA 示例插件迁移到非插件版主程序，并让前端页面由后端声明驱动。迁移按阶段实施和验收，未完成开发的 `dev-plugin-v2-latest` 只作为设计与代码参考，不整体合并。当前分支为 `refactor/plugin-migration-v3`；当前 HEAD 为 `81531182`（`892883fa` 为此前迁移检查点），本轮没有切换分支或声称已同步最新 dev。

## 通用约束与交付门槛

- 每阶段先检查当前 `dev` 的相邻实现和依赖，再做最小范围变更；不得将旧插件分支整体合并到新基线。
- API 采用 schema-first 流程；若后端 schema 变化，前端 API 代码只通过仓库生成器更新，不手改生成文件。
- 配置采用已确认的新配置体系，旧 `ConfigBase` / `ConfigItem` 不参与运行；模块职责与依赖遵循用户判定的迁移方案及项目 Skills，不因旧文档重启兼容层。
- 底层迁移范围和具体实现思路先交用户判定，记录已确认与待定事项；遇到未迁移服务报错时，先诊断，不自动扩大迁移。
- 用户可见改动按仓库规则添加一个 changelog 碎片；不改 `CHANGELOG.md`、版本号或 `res/version.json`。测试脚本遵循 `tests/AGENTS.md`，默认作为本地一次性验证，不提交。
- 每阶段完成后记录变更范围、验证命令和未解决风险，再进入下一阶段。阶段验收未通过时先修复，不推进后续依赖阶段。
- 后端阶段不以旧前端页面可用性为完成条件，也不为修复旧页面临时恢复旧框架；整体后端验收是前端迁移的前置门槛。
