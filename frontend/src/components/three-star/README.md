# 三星引力场

可选首页装饰，沿用 `homeSatelliteStyle` 的 Electron 配置持久化。默认仍为
`classic`；新组件按需加载，只在首页原装饰区域挂载。

## 边界

- `physics.ts`：三个点质量的初值、三对引力、积分、诊断、暂停和重置。
  不依赖 Vue、DOM、GPU 或任务状态。
- `scene.ts` / `starShaders.ts` / `fluid.ts`：只消费已接受快照，球体、相机、
  体积星冕和世界空间三维流体；不能获得积分器的可写缓冲。
- `ThreeStarGravity.vue` / `stores/threeStar.ts` / `taskFeedback.ts`：配置入口、
  主题、低性能模式、页面生命周期和共享任务状态。

## 物理模型

采用无量纲 `G=1`、未软化牛顿引力。每颗星有正质量、三维位置和速度，
状态使用 `Float64Array(18)`。每对引力同时累加到两个天体的加速度，符号相反、
各按对方质量加权。构造时转换到质心参考系，之后不修正能量、动量或轨道。

`DEFAULT_BODIES` 是本功能的**自定义初值**，不是已有周期解的引用，不保证周期、
稳定或混沌。三个质量均为 1，位置/速度逐项保存在源码中；重置恢复相同初值。
不融合、不碰撞反弹、不限速、不加中心力或随机力。球体半径 0.17 仅为艺术尺寸，
不是碰撞或终止半径。

采用 Dormand–Prince 5(4) 嵌入式显式 RK：七个 stage，第五阶结果推进，
四/五阶差估计局部误差。取全部 18 个分量的最大归一化误差：

```text
max |error[k]| / (atol + rtol * max(|old[k]|, |candidate[k]|)) <= 1
rtol = 1e-9, atol = 1e-11
```

超限拒绝整步，按 `0.9 * error^(-1/5)` 缩步；接受后最多增长四倍。
这是自适应 RK，**不声称辛积分或长期逐点准确**。相比固定步长 Verlet，
该方案能直接拒绝近遇中的误差超限步；相比 DOP853，其七 stage 与较小系数表
更容易在仅 18 个状态量的本地实现中核对。暂不使用 FSAL 缓存或稠密输出，
渲染直接读取最后接受状态。

- 允许步长：通常 `1e-7 <= h <= 0.02`，到目标时刻的最后一个余步可更短。
- 近遇上限：`0.03 * sqrt(r^3/(mi+mj))`，基于成对引力时间尺度先行缩步。
- stage 距离小于 `1e-4` 时拒绝并缩步；最小步长仍失败、近遇时间尺度要求更小步长、
  或无法用浮点数继续推进时，保留最后有效状态并暂停。非有限 stage 也先拒绝缩步，
  无法恢复时暂停。该终止距离是数值策略，不是恒星表面。
- 每帧至多 64 次尝试和约 3 ms 软预算（只在整步之间检查，无法抢占一个 stage）。
  默认每秒墙钟推进 1 个物理时间单位（原为 0.35），页面内可选 0.5×/1×/2×/4×；
  倍速只乘目标模拟时长，不放大积分步长。墙钟片段最多 50 ms。预算耗尽直接少推进，
  不存待追赶的目标时间；不放宽容差。
- 能量诊断分母为初始 `K0 + |U0|`，避免总能量近零造成虚假巨大相对误差。
  同时可读取总动量、角动量的绝对漂移。诊断不反馈修改物理状态。

数学系数依照 [Dormand & Prince (1980)](https://doi.org/10.1016/0771-050X(80)90013-3)，
与 [Apache Commons Math 系数表](https://commons.apache.org/proper/commons-math/javadocs/api-3.6.1/src-html/org/apache/commons/math3/ode/nonstiff/DormandPrince54Integrator.html)
核对。实现独立编写，仅使用数学系数，不复制 Apache 或 SciPy 求解器，不新增运行时依赖。

## 视觉、流体与合成

复用已有 `three`，不增加依赖。64×48 分段的不透明球体在真实 xyz 位置透视绘制，
表面宽尺度纹理、细丝与边缘光只表达艺术恒星；星冕使用三维噪声密度壳，
以世界空间射线积分绘制，不再使用朝向相机的平面贴片。
白金/冰蓝/紫红分别表示调度/执行/反馈，任务光脉冲也是小球，业务事件只改变光效。
这些不是恒星内部、等离子体、宇宙介质或磁流体的物理模拟。

背景替换为本地打包的 NASA SVS [Deep Star Maps](https://svs.gsfc.nasa.gov/3895/)
4K 球面星图（4096×2048，约 2.24 MiB JPEG），依据真实星表位置、亮度与颜色绘制，
不是望远镜单幅照片，也不代表三体真实所在天区。使用原始 JPEG，不使用预览缩略图。
材质将方向映射到球面坐标，随视角产生正确旋转；背景无椭圆遮罩，限于原装饰 stage。
来源、署名与公有领域说明见 [素材说明](../../assets/three-star/README.md)。
星图约占 32 MiB RGBA 纹理，含 mipmap 约 42.7 MiB；不是零成本背景。

先评估现有 `FluidCursorOfficial.vue` 的平流、压力投影、扩展检测、FBO 与释放：
它的 xy 平面速度及四邻域压力 shader 不支持真实 xyz 体积，鼠标输入和全屏生命周期
也不适用。本次保留原光标完整代码，用相同的 stable-fluids 思路独立编写六邻域
三维 stencil，没有挂载光标、复制鼠标喷射或保留无消费者的公共 shader 抽象。
未复制上游软件源码；可对照 [GPU Gems 38](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-38-fast-fluid-dynamics-gpu)
的半拉格朗日平流/投影方法。其教材二维公式按 xyz 扩展，不宣称高精度流体求解。

`fluid3dShaders.ts` 存储 48³ 三维体素，以 8×6 切片 atlas（384×288）打包；
atlas 是存储布局，速度有 xyz 三个分量，平流沿 xyz 回溯，压力用六邻域，
Z 跨层插值与层内双线性过滤构成三线性采样，不是屏幕二维流体或粒子替代。
使用 WebGL2 RGBA16F，共七张场纹理（速度/染料/压力各双缓冲加散度），
约 5.91 MiB 颜色存储，不含驱动、星图、画布、体积积分图像和几何缓冲。
逐张实际检查 framebuffer；半浮点线性过滤由 WebGL2 支持。
每次更新顺序为速度平流、有限动量/染料注入、散度、清压力、12 次 Jacobi、
投影、染料平流；没有额外涡量增强。有限网格/迭代是视觉近似，不承诺散度为零。

固定流体域为物理世界 `[-3,3]³`，其边界仅影响视觉气体；天体可自由离开，
不裁剪、不施力、不拉回，也不在域外伪造尾迹。相机移动只改变射线，不清场，
避免旧版屏幕空间流体随视差错位。射线按前后顺序积分染料与星冕，
求三颗不透明球体的最近正向交点来截断射线，后方尾迹不会无条件覆盖星球表面。
体素与三维噪声共享世界坐标，所以交汇/遮挡不依赖二维投影距离。
这不是完整辐射传输，有限体素与步进会损失小尺度细节。

流体时间步独立，最多 1/30 s，每显示帧最多一次。速度与染料耗散均按秒定义，
每颗发射源最多 8 个路径补样、合计 24 个；补样分摊总注入量而不倍增。
每轴源速度限制 ±0.35 域单位/s，场速度限制 ±0.6，染料每通道限制 0..2。
过长跳跃断开端点；静止/暂停、后台或数值故障不继续注入或推进。
恢复/重置清除流体、端点和待播放光效。星冕覆盖率最多 0.78，颜色有限，
采用预乘透明度存储、普通透明合成，禁止无限加法叠白。

最终画布与体积积分分辨率分开：画布逻辑上限 1920×720，DPR ≤2，
总绘制像素 ≤250 万；球体和 4K 星空直接按最终画布绘制，开启可用的 MSAA。
柔和体积效果另在 ≤960×384 的图像积分（通常为画布尺寸的 65%），
每条射线最多 288 步，体素粗步 0.09、星冕局部细步 0.018，空区间跳过，
再线性放大合成。不会靠放大流体网格假称全画面高分辨率。
相机平滑拉远至距离上限 80，视锥之外用方向标注，不改变物理坐标。

## GPU 与生命周期

实际创建 WebGL2（`failIfMajorPerformanceCaveat`）、检查 float attachment 扩展、
最大纹理尺寸和 framebuffer。Electron 只读 `getGPUFeatureStatus()` 的
`webgl2` / `gpu_compositing`，并结合 unmasked renderer 排除 SwiftShader 等软件路径；
浏览器或旧 preload 缺少 IPC 时保守识别已知硬件 renderer。无法确认则静态降级。
这些是能力门控，不能当成实机 GPU 路径或性能的测量证明。

目标帧率上限 30；上述限额是固定预算，不是实测帧率保证。
低性能模式和 `prefers-reduced-motion` 只显示 CSS 静态图，释放 GPU 资源。
失去上下文/异常同样静态降级；恢复上下文时重建，保持物理状态且等待手动继续。
离开首页、离开视口或窗口/文档隐藏时停钟，返回保持暂停，不补算隐藏时间。
用户的手动暂停和求解器会话状态由 Pinia 保留；重置清空流体与光效后等待继续。
自动任务暂停沿用性能 store，用户可对当前任务周期暂时恢复动效。

场景拥有几何、材质、纹理、render target；组件拥有 RAF、ResizeObserver、
IntersectionObserver、媒体查询、可见性和 task listener，卸载分别释放。
没有新增后端 API、业务轮询、WebSocket 订阅或数值 Worker。

## 专项来源与事件

徽标读取 `useTaskRuntimeState().scriptStatusesByType`，其中 `running` 已由实际
`task_info` 的脚本/用户运行状态汇总；不读取任务 `scripts` 全名单作为运行列表。
复用 `SCRIPT_LOGOS` 和 `SCRIPT_LABELS`，显示一项加 `＋N`。MaaFW 暂按类型聚合，
不新增项目配置读取。WS 未连接时不显示专项/结果，物理展示可独立继续。

`onTaskRuntimeEvent` 复用已有常驻状态分发。`created` 只触发一次调度光脉冲，
最终 `completed.outcome` 才触发成功、失败或中止光效。入页先登记已知任务，
快照不触发光效；暂停时消耗事件但不排队。单个完成事件不会改变全局空闲状态。
