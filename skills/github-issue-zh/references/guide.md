# Issue 描述规范（完整）

对应 Skill：`github-issue-zh`。执行代写前若需细节，阅读本文。

## 写什么

1. **背景 / 问题**（1～3 段）：用户或系统当前遇到什么、为什么需要改。
2. **期望**（条列）：要达成什么能力、用户侧可见行为是什么。

**条理性**：精简不等于一整段。多个可独立理解的功能点应分点/编号或小标题，每点一件事；子条目保持用户视角。

## 不写什么

- 实现步骤、推荐 API、Schema 字段设计
- `app/...`、`frontend/...` 等代码路径与行号
- 验收标准 checkbox、范围表、与非目标列表
- 「供开发参考」「欢迎维护者收窄范围」等元评论

## 篇幅

- 理想：**约 150～400 字**（复杂可至 ~600 字，再长应拆 issue）。
- 多条独立需求：优先拆成多个 issue；若合并，用编号或分点区分。

## 模板

```markdown
## 背景

[现状与痛点，说明「为什么」]

## 期望

### [功能点 1 的简短标题]

- [该功能要做什么]

### [功能点 2 的简短标题]

- ...
```
